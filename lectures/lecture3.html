Lecture 3: HTML Forms and Media

Interactive user inputs, native multimedia embedding, tables, and semantic layouts

Summary

This lecture explores user data collection through HTML5 forms, native audio and video multimedia embedding, structured data presentation with tables, and modern semantic page layout elements. It teaches input controls, form methods (GET vs. POST), validation attributes, merged table cells, and block versus inline formatting.

Topics Covered:

  • HTML Forms & User Inputs
    • Form Structure: <form>, action, and method (GET vs. POST)
    • Input Controls: text, email, password, number, date, radio, checkbox
    • Dropdowns (<select>, <option>) & Multiline Text (<textarea>)
    • HTML5 Validation Attributes: required, placeholder, pattern, min, max
  • HTML5 Native Multimedia
    • Audio Embedding: <audio controls> and <source>
    • Video Embedding: <video controls width="..."> and formats (MP4, WebM)
  • HTML Tables
    • Table Grid: <table>, <tr>, <th>, <td>, <caption>
    • Semantic Table Sections: <thead>, <tbody>, <tfoot>
    • Cell Merging: colspan (column span) and rowspan (row span)
  • Block vs. Inline & Semantic HTML
    • Block-level (<div>, <p>, <h1>) vs. Inline (<span>, <a>, <strong>)
    • Semantic Landmarks: <header>, <nav>, <main>, <section>, <article>, <footer>
Example Code:
<!-- Student Registration Form Example -->
<form action="#" method="POST">
    <div>
        <label for="username">Full Name:</label>
        <input type="text" id="username" name="username" placeholder="John Doe" required>
    </div>
    <div>
        <label for="useremail">Email Address:</label>
        <input type="email" id="useremail" name="useremail" placeholder="john@example.com" required>
    </div>
    <div>
        <label for="course">Select Course:</label>
        <select id="course" name="course">
            <option value="web">Web Technologies</option>
            <option value="db">Database Systems</option>
        </select>
    </div>
    <button type="submit">Submit Registration</button>
</form>

Detailed Theoretical Concepts

1. Form Submission Methods: GET vs. POST

Feature HTTP GET Method HTTP POST Method
Data Transmission Appends data directly to the URL in query strings (e.g. ?user=ali&id=1). Sends data in the HTTP request body; invisible in browser address bar.
Security Insecure for sensitive data (passwords appear in URL, browser history, and server logs). Secure for credentials and sensitive inputs.
Data Length Limited by URL character limits (~2048 chars). No arbitrary size limits (suitable for file uploads).
Best Use Case Search queries, filtering, bookmarkable pages. Registration forms, logins, transactions, file uploads.

2. Merging Table Cells: Colspan and Rowspan

In university exams, cell-merging is frequently tested:

  • colspan="N": Merges N horizontal columns into a single cell. (Example: <th colspan="2">Student Name</th>)
  • rowspan="N": Merges N vertical rows across multiple lines into a single cell.

3. Block vs. Inline Comparison

Category Line Behavior Width & Height Dimensions Common Elements
Block Elements Always starts on a new line and stretches across the full available width. Accepts width, height, margin-top, and margin-bottom. <div>, <p>, <h1>–<h6>, <form>, <table>
Inline Elements Does not start on a new line; flows inline with adjacent text. Ignores width and height; vertical padding/margin do not affect document flow. <span>, <a>, <strong>, <em>, <label>
Common Student Mistakes:
  • Missing the name attribute on input tags: if an input lacks name, its value will NOT be submitted when the form sends data to the server.
  • Failing to associate <label for="id"> with the matching <input id="id">, which ruins accessibility and makes it impossible to click the text to focus the field.
  • Placing content directly inside <table> without enclosing it in a <tr> row.

Lecture 3 Viva Questions & Answers

Q1: Why is Semantic HTML important for websites?
Answer: Semantic elements (like <header>, <nav>, <article>, <footer>) clearly describe their meaning to both the browser and screen-readers. They significantly improve search engine optimization (SEO), code maintainability, and accessibility for disabled users.

Q2: What is the purpose of the required attribute in HTML5 inputs?
Answer: It activates native browser-level client-side validation, preventing form submission if the user leaves the input field blank.

Q3: How do you embed a native video file with user playback controls?
Answer: Using <video controls width="600"><source src="video.mp4" type="video/mp4">Your browser does not support HTML5 video.</video>.
